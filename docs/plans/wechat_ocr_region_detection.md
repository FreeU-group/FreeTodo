# 微信 OCR 区域检测技术文档

## 概述

微信截图的 OCR 处理需要将一张完整的微信窗口截图分割为多个功能区域，并对每个区域进行针对性的处理。本文档描述当前的区域检测逻辑、算法原理和设计决策。

核心原则：**不依赖绝对像素值或硬编码颜色**，所有检测基于相对比例、亮度变化趋势和结构特征，以适应不同分辨率和 DPI。

## 整体流程

```
完整窗口截图
 │
 ├── Step 1: 侧边栏裁剪 ──→ 聊天区 ROI
 │
 ├── Step 2: 标题分隔线检测 ──→ 标题区 + 消息区
 │
 ├── Step 3: 标题区 OCR ──→ 聊天名称、聊天类型（私聊/群聊）
 │
 └── Step 4: 消息区 OCR + 逐行分类
      ├── 时间戳行（居中、字小、含时间格式）
      ├── 编辑框文字（背景色匹配编辑框）
      ├── 群聊昵称行（字小、紧挨消息）
      ├── 发送按钮（右下角"发送"）
      └── 正常消息 → 说话人归属（颜色检测 > 位置检测）
```

## Step 1: 侧边栏裁剪

**目标**：将左侧联系人列表从截图中移除，只保留右侧聊天区域。

**文件**：`client/proactive_ocr/priors/wechat.py` → `_find_sidebar_boundary()`

### 算法：列背景亮度水平交叉检测

微信深色模式下，侧边栏背景亮度（~45-50）高于聊天区背景（~25-30）。利用这个差异定位分界线。

```
1. 转灰度图
2. 取 x=5%~55% 宽度范围，y=10%~90% 高度范围
3. 对每列计算第 25 百分位亮度（排除头像、文字等亮色内容，只取背景色）
4. 平滑去噪（滑动窗口均值，窗口宽度 = 列数 / 40）
5. 计算侧边栏亮度水平 = 平滑后最大值
6. 计算聊天区亮度水平 = 右半部分平滑后最小值
7. 阈值 = (侧边栏水平 + 聊天区水平) / 2
8. 从左到右扫描，找最后一个从高于阈值跌到低于阈值的列 = 分界线
```

**为什么用第 25 百分位而不是中位数**：聊天区有气泡（绿色/灰色）和文字等亮色内容，中位数会被拉高，模糊了与侧边栏的差异。第 25 百分位只看最暗的 25% 像素 ≈ 纯背景色，差异更清晰。

**为什么取"最后一个"交叉点**：图像从左到右有两个亮度变化：图标栏→侧边栏（暗→亮）和侧边栏→聊天区（亮→暗）。需要的是后者。

### 无侧边栏处理

如果检测到的 x 超过图片宽度的 45%，判定为无侧边栏（可能是独立聊天窗口或侧边栏收起），使用全图（`split_x = 0`）。

## Step 2: 标题分隔线检测

**目标**：在聊天区 ROI 中定位标题栏和消息内容的分界线。

**文件**：`client/proactive_ocr/priors/wechat.py` → `find_title_divider_y()`

### 策略一：脉冲检测（优先）

标题栏和消息区之间常有一条 1-4 像素宽的分隔线，在逐行扫描时表现为亮度脉冲——某行的亮度突然偏离上下行然后恢复。

```
1. 取 ROI 顶部 20% 区域，水平取 40%~85% 的条带
2. 计算每行的平均亮度
3. 计算一阶差分
4. 逐行扫描：找 |diff[y]| > 10 的位置
5. 在 4 行窗口内查找 diff 符号相反的另一个大差分
6. 找到 → 返回该行作为分隔线位置
```

**为什么用窗口而不是严格相邻**：分隔线可能 2-4 像素宽，差分的正负峰可能不在相邻行。

### 策略二：阶跃检测（fallback）

当没有明显分隔线（如微信某些版本或特殊布局），标题区和消息区只是背景亮度不同，没有明显的细线。

```
1. 从 ROI 高度 25% 处开始扫描（跳过顶部窗口装饰）
2. 找 |diff| > 10 且之后 8 行亮度持续在新水平的位置
3. 第一个满足条件的行 = 分隔线
```

**为什么从 25% 开始**：ROI 顶部可能有窗口标题栏边界产生的亮度变化，这不是聊天分隔线。

### Fallback 链

```
find_title_divider_y()
 ├── 策略一（脉冲）→ 成功则返回
 ├── 策略二（阶跃）→ 成功则返回
 └── 返回 None

get_title_divider_y()
 ├── find_title_divider_y() → 成功则返回
 └── 行亮度变化估算 → 成功则返回
 └── 固定比例 8% 兜底
```

## Step 3: 标题处理

**标题来源优先级**：

1. 标题区 OCR 结果（最准确，直接读取渲染的文字）
2. `window.title`（操作系统级窗口标题，作为 fallback）

**聊天类型判定**：

用正则匹配标题文字末尾的成员数后缀：

```python
re.compile(r"[(\uff08]\s*\d+\s*[)\uff09]\s*$")
```

- 匹配 `(55)` 或 `（55）`（半角/全角括号）→ 群聊
- 不匹配 → 私聊

## Step 4: 消息区逐行分类

OCR 只对消息区（分隔线以下）执行。每个 OCR 行按以下优先级依次判断：

### 4a. 时间戳行

微信在消息之间插入居中的小字时间戳（如"星期六 16:00"、"昨天 23:20"）。

**判定条件**（多信号组合，满足任一路径即可）：

路径 A：居中 + 字小 + 正则匹配
- `bbox 中心` 距 ROI 中线偏差 < 30%
- `bbox 高度` < 中位行高 × 0.80
- 正则匹配时间格式（`HH:MM`、`昨天 HH:MM`、`星期X HH:MM` 等，支持全角冒号）

路径 B：居中 + 窄 + 字小 + 有数字 + 有冒号
- 前三项同上 + `bbox 宽度` < ROI 宽度 × 0.35
- 文本含数字 + 含 `:` 或 `：`

**时间标准化**：相对时间自动转换为 `YYYY-MM-DD HH:MM` 格式（昨天→减1天，星期X→往前找最近的周X）。

### 4b. 编辑框文字

用户正在输入但未发送的文字在编辑框中，左对齐，容易被误识为对方消息。

**判定方法**：在 bbox 上下左右扩展 8px 采样 6 个点的背景色，与编辑框预设背景色对比。过半数匹配 → 判定为编辑框文字 → 跳过。

### 4c. 群聊昵称行

群聊中，对方消息上方有一行小字显示发言人昵称。

**判定条件**（仅群聊生效）：

满足以下**任一**组合：
- `bbox 高度` < 中位行高 × 0.92（字号小）
- 或 `文本长度` ≤ 20 字 且 `bbox 宽度` < ROI 宽度 × 0.35（短且窄）

加上：与下一行的 y 间距 < 中位行高 × 1.5（紧挨消息）

检测到后，该行文字存为 pending_nickname，归属给紧随其后的消息。

### 4d. 发送按钮

`文本 = "发送"` 且位于右下角（y > 88% 高度, x > 75% 宽度）→ 跳过。

### 4e. 正常消息 → 说话人归属

**方法一（颜色检测，优先）**：

在 bbox 左侧或右侧采样 3 个点的平均颜色，与气泡预设颜色对比：
- 匹配绿色气泡 → `[我]`
- 匹配灰色气泡 → `[对方]`

**方法二（位置检测，fallback）**：

`bbox 中心 x` 与 ROI 中线比较：
- 中心偏右 → `[我]`（右侧绿色气泡）
- 中心偏左 → `[对方]`（左侧灰色气泡）

## 最终输出格式

```
[私聊][振荡周期huaze]
[时间] 2026-03-22 12:02
[我] 我们在这个4楼的八合里，益田假日里，你们早点过来吧
[振荡周期huaze] 好诶
[振荡周期huaze] 我们打上车了
[时间] 2026-03-22 12:24
[振荡周期huaze] 我们到了
```

群聊示例：
```
[群聊][橡树园@芒果创业交流群]
[对方] @8-102你好，我将此消息发给小区，已经通知
[物业管理处安全人工智能维修] @8-102你好上班后我将到现场检查反馈给领导
[时间] 2026-03-22 12:11
[对方] 再次提醒各位居民不要随意高空抛物
```
