# Docs Index

This folder is organized by document purpose so root-level materials and existing docs are easier to browse.

## Structure

- `architecture/`: architecture designs, module designs, technical diagrams, and audio pipeline docs
- `guides/`: setup, deployment, and end-to-end usage guides
- `plans/`: feature plans, research notes, change logs, and backlog-style tracking docs
- `reports/`: review and audit reports
- `examples/`: sample payloads and supporting example files

## Documentation Expectations

- Add or update a doc in `docs/` in the same commit as any code change.
- Prefer updating an existing page when the behavior belongs to a documented module or workflow already.
- Use `architecture/` for module responsibilities, boundaries, interfaces, and system behavior.
- Use `guides/` for operator or developer instructions, setup steps, and usage flows.
- Use `plans/` for in-progress proposals, investigation notes, and dated change tracking that may later be folded into a stable doc.
- Keep docs concise and collaborator-friendly so agents and teammates can quickly understand the current state of a module.
